Proposed spec wording

Added to EXTENSION_SPEC.md §5, where comments are kept:

What the reviewer types into Pipeup on a page can't be seen by the page: not the words of a comment, reply or edit, nor the keys pressed, nor what is pasted or dictated there. Typing looks and works as it does on a page with Pipeup built in: @mentions, add-ons' buttons in the box (Emoji, Voice), Enter to send, Shift+Enter for a new line, Esc to cancel, undo, and the browser's spelling and input methods. The page sees only that Pipeup's box has the focus.

What stays the same

  • How the box looks, grows with the words, and where it opens.
  • @mentions, Emoji and Voice in the box; Enter, Shift+Enter, Esc, undo, Tab in and out.
  • Spelling, Japanese and Chinese input, words written right to left.
  • Pages with Pipeup built in: no frame, nothing changes there.
  • The side panel and the toolbar panel: typing there never touched the page.

How we'd know it works

  • A test types in every kind of box (new comment, reply, edit) and checks the page's own listeners heard no key, input, paste or composition event.
  • One test for each key Pipeup acts on, so none is lost on the way.
  • A page that frames the extension's typing page itself gets a box that does nothing.
  • The hand checklist gains steps for input methods and dictation in Chrome, Firefox and Safari.

The design note, with how it's built and the risks: docs/design/extension-private-typing.md.
