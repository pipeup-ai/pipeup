The page, when the extension adds Pipeup

On a page that has Pipeup built in, the corner control is how a reviewer reaches Pipeup. With the extension, the toolbar button already does that job. So when the extension adds Pipeup, the corner control steps aside, and the page shows only the comments themselves.

2. Where each of the control's jobs goes

Start and stop comment modeThe toolbar panel's first row, or ⇧⌥C as before. Esc stops it.
Show how many comments are openThe number on the toolbar button (already there).
Open the menu (name, Copy comments, Theme, Hide comments, add-ons)The panel's Pipeup's menu row opens Pipeup's own menu on the page, unchanged.
Open All commentsThe panel's All comments row.
Show that comment mode is onThe toolbar button's number turns green while comment mode is on, and comment mode's hint says how to stop, as today.
Hold Pipeup's short messages ("Resolved", a mention)They show in the same corner, on their own.

Nothing new is built in Pipeup for this: hiding the control, opening the menu and All comments, and turning comment mode on are the page API that pages with their own Comment button already use (§4a).

  • Start commenting is first, with its switch and shortcut, as it is nearest the control in Pipeup's own menu. Choosing it closes the panel and turns comment mode on, so the next click on the page picks a block.
  • All comments and Pipeup's menu close the panel and open Pipeup's own on the page, with focus in them. Nothing of Pipeup's menu is copied into the panel, so add-ons' rows keep working.
  • Off, the panel is as now: Comment on this page. Choosing it also turns comment mode on, since that is why the reviewer pressed it.

While comment mode is on, the toolbar button's number turns from violet to green, and the button stays lit. Comment mode's hint and the block outline work as they do now. Esc, ⇧⌥C or the panel's switch stops it.

With no corner control, this is how the reviewer can tell at a glance that a click on the page will pick a block rather than follow a link.

5. The spec change

An addition to docs/EXTENSION_SPEC.md §3 and §4:

  • When the extension adds Pipeup to a page, Pipeup's corner control is hidden: the page shows the comments and nothing else of Pipeup's until the reviewer asks. A page with Pipeup built in keeps its own control.
  • With Pipeup on, the toolbar panel offers Start commenting (with its switch and shortcut), All comments (with the open count), Pipeup's menu, Always on for this site and Turn off on this page.
  • Comment on this page turns comment mode on as it adds Pipeup.
  • While comment mode is on, the toolbar button shows it: its number turns green, and says "on" when there are none.
  • A setting in the extension, Show Pipeup's button on pages, brings the corner control back for reviewers who want it. Off by default.

6. Decisions (agreed 9 November 2026)

Hide the corner control by default? Agreed: yes, with the setting to bring it back. The other choice is to keep it, as on pages with Pipeup built in.

How comment mode shows. Agreed: in the toolbar button (green number, lit button). The other choice is a small "Commenting · Esc" label in the page's corner while it's on, which is clearer but puts Pipeup back on the page.

Does Comment on this page also start comment mode? Agreed: yes. The other choice is only adding Pipeup, so existing comments show first.

What changes, in one place

  • With the extension, the site's corner is left alone; the toolbar is the one way into Pipeup.
  • The panel gains Start commenting, All comments and Pipeup's menu.
  • Unchanged: comments on the page, the menu itself, pages with Pipeup built in, and Pipeup's code.
