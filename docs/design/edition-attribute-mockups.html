Editions in one page: comments stay with their edition

Muse's briefing is one page with a new edition every day. Today Pipeup sees one document, so Monday's comments turn up on Tuesday's news, marked Moved. #109 works around it by giving each edition its own identity, which needs a script in the shell and splits the history into separate documents. This proposal lets the page simply say which edition it shows.

What changes

  • A page can name the edition it shows with one attribute, data-pipeup-edition, and change it when the next edition is swapped in. Pipeup follows the change without a reload.
  • Each comment remembers its edition. Comments from other editions never show on the page, are never matched to the new edition's content, and are never marked Moved for it.
  • The comment control counts this edition only. Earlier editions' comments wait in All comments, under a folded Earlier editions heading with their count.
  • An earlier edition's thread still opens from All comments, with what it was about, and can be replied to or resolved. It goes to that edition only when the page tells Pipeup how.
  • Copy for my agent carries this edition's open comments, and says how many on earlier editions it left out.
  • It's still one document: one identity, one shared copy, no script needed. The per-edition identity in #109 stays valid for pages that want editions kept wholly apart, and for older versions of Pipeup.

Screen 1 · What the author adds

One attribute on <html>, set again when the next edition is swapped in. No script runs before Pipeup, and the identity never changes.

<!-- the shell, fixed --> <html data-pipeup-doc="k7Hq…:key…" data-pipeup-edition="2026-10-21"> … // when the shell swaps in the next edition document.documentElement.dataset.pipeupEdition = edition.date;

The value is shown as written ("the 2026-10-21 edition"), so a page may use a readable name ("Tue 21 Oct"). It must be the same every time that edition is shown.

Proposed spec wording

Changes to §4 (Adding Pipeup), §8 (Staying attached), §7 (All comments), §15 and §15b (agents), and §19.

§4 · Adding Pipeup to a page
Authors can optionally mark up … an edition: a page that shows a new edition in the same shell (a daily briefing, say) can say which edition it is showing, and say so again when the next one is swapped in.
§8 · Staying attached on changing pages
On a page that names its edition, every new comment remembers the edition it was made on. Comments from another edition never show on the page, are never matched to the content of the edition showing, and are never marked Moved for it. When the page names a new edition while it is open, Pipeup follows without a reload.
On a page that names its edition, a comment made before the page named one counts as an earlier edition's.
§7 · All comments, and the comment control
The comment control counts the open comments on the edition showing. All comments lists them first, then, folded under Earlier editions with how many open threads they hold, the threads of other editions, each saying which edition it is from.
An earlier edition's thread opens on its own with a snapshot of what it was about, and can be replied to, reacted to and resolved. It goes to that edition only when the page tells Pipeup how.
§15 · Agent support
When each edition is meant to be reviewed on its own, the publisher gives each edition its own document identity …
When each edition is meant to be reviewed on its own, the page names the edition it shows (§4), and agents that publish such pages do so. A page that wants editions kept wholly apart, or that runs a Pipeup without editions, gives each edition its own document identity instead.
§15b · Copy for my agent
On a page that names its edition, the copied text carries the open comments on the edition showing, and says how many open comments on earlier editions it left out.
§19 · Open questions
Editions: whether a page should be able to say which edition it is showing …

Open questions

1. Do earlier editions' open comments count on the control?

Recommended: no. A daily page would pile up yesterday's threads forever and the dot would never clear. They wait, counted, under Earlier editions in All comments.

2. Comments made before the page named its edition

Recommended: they count as an earlier edition's ("Before editions"), so a page that adopts the attribute stops the old ones landing on today's news at once. The alternative, letting them float onto whatever edition shows, keeps today's problem for them.

3. Editions and identities together

Recommended: the attribute is the default advice; a separate identity per edition stays documented for pages that want editions wholly apart (separate shared copies, nothing listed across them) and for Pipeup versions before this one.
