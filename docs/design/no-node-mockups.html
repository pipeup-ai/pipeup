Pipeup's agent and sharing features, without Node

Ada is planning a trip to Lisbon that starts Friday. Claude made the itinerary as a page with Pipeup, and Ada left six comments on it. Ada asked Claude to act on them and to let a friend, Lee, see the page. Claude offered three options, and two of them began with installing Node.js from nodejs.org, which asks for a password. Ada has never heard of Node. Neither job needs it.

What changes

  • Copy for my agent says which ways are open, lightest first, and what each one needs. The agent offers copy and paste first, and never asks the person to install anything to answer one round of comments.
  • An agent with a shell uses the clipboard. On a Mac it reads what Ada copied with pbpaste and puts its replies back with pbcopy, so Ada never selects text in a terminal. Both come with every Mac.
  • Or it leaves its replies in a file next to the page. The page finds them and asks Ada before adding them, as it does for a paste. No signing, so nothing to install.
  • A single Pipeup program does everything npx pipeup does today, including the live link and signed replies, with no Node. One line installs it into Ada's home folder, with no password.
  • A setup page on Pipeup's website sets up sharing in the browser, with nothing to install. It lists the sharing services and picks none. Sending Lee the file stays the lightest way, and needs no service at all.

What stays the same

  • Nothing leaves Ada's computer unless Ada chooses a sharing service. The clipboard, the replies file, the live link and the setup page all stay on Ada's computer or in Ada's browser.
  • The setup page runs in Ada's browser. The page file and comments go to the service Ada chooses, never to Pipeup's website.
  • No analytics or telemetry. The program and the setup page send nothing about Ada anywhere.
  • Agents still only reply and mark threads addressed. Replies an agent didn't sign still show as "pasted by you", and the page still asks before it adds any of them.

How an agent picks

The order the copied text, the skills and llms.txt all give. The agent offers the first rung that works, and moves up only when the person asks for more.

Copy and paste, always

Works for every agent, on any computer, with nothing installed. The agent offers this first for one round of comments.

The clipboard, or a file next to the page

When the agent can run commands on the person's computer. It reads the clipboard only right after the person says they copied, and hands its replies back on the clipboard, or in a file the page asks about. Nothing to install.

Pipeup's command, if it's already here

When ~/.pipeup/bin/pipeup or npx is already on the computer: signed replies, and the live link, so replies appear by themselves.

Install the Pipeup program, only if asked

When the person wants replies to appear by themselves. The agent says what it installs, where, how big it is, that it won't ask for a password, and how to remove it, and waits for a yes. It never suggests Node to someone who doesn't have it.

Sharing is a separate question

Never offered as part of answering comments. When the person asks, the agent says first that sending the file needs nothing more, and that seeing each other's comments on the page needs a sharing service the person picks, set up on the setup page or with Pipeup's command.

Proposed spec wording

Changes to §11 (Shared comments), §15b (Answering; What agents are told), §15c (Starting it), and a new §15g.

§11 · Shared comments (sharing add-on)
The author sets up sharing with the command-line tool.
The author sets up sharing with Pipeup's command, or with the setup page on Pipeup's website, which needs nothing installed. Either writes the sharing line into the file, says how long the chosen service will keep the shared copy, and shows the stop key once, separately from the file.
The setup page works in the author's browser. The page file and its comments go only to the service the author chooses, never to Pipeup's website. It lists the services it knows with, for each, who runs it, how long it keeps comments and what it can see, and picks none for the author.
Sending someone the page file needs no service: they comment on their copy, and their comments come back when they copy them and send them.
§15b · Answering
An agent that can write files on the person's computer but has no Pipeup command can leave its replies block in a file next to the page. With the agents add-on, the page finds it when it opens and when the person checks for replies, says in words what it found as it does for a paste, and adds nothing until the person agrees. Replies not signed by an agent the page lists show as "pasted by you".
Answering never needs anything installed.
§15b · What agents are told
Copy for my agent lists the ways of answering open on this page, lightest first, and what each needs: a replies block, always; the clipboard or a file next to the page, for an agent that can run commands on the person's computer; and the reply command and the live link, where Pipeup's command is already there. It says what the page knows (opened from a file or a website, which kind of computer, whether a live link is running, whether the page lists an agent) and tells the agent how to check the rest.
An agent offers the lightest way that works first, in plain words, and never asks the person to install anything to answer comments. It offers to install Pipeup's program only when the person wants replies to appear by themselves, and first says what it installs, where, how big it is, whether it asks for a password, and how to remove it.
An agent that can run commands on the person's computer may read the comments from the clipboard right after the person says they copied them, and only then. It may put its replies block on the clipboard and tell the person to choose Paste my agent's replies.
Sharing is never offered as part of answering comments. When the person asks to share a page, the agent says first that sending the file needs nothing more, and that seeing each other's comments on the page needs a sharing service the person picks.
§15c · Starting it
The author starts a link for a page file with one command on their own computer.
The author starts a link for a page file with one command on their own computer, from Pipeup's program or from Node; both behave the same.
§15g · Pipeup's commands without Node (new)
Every Pipeup command is also available as one program for macOS, Linux and Windows that needs nothing else installed. It behaves exactly as the same version's commands through Node.
One line installs it, into one folder in the person's home folder, without a password and without changing anything else on the computer, so agents find it in a known place. Before writing anything, the installer says what it will put where and how big it is, and waits for a yes.
It checks that what it downloaded is the published release, and it can update and remove itself.
It sends nothing about the person anywhere. Its only network requests are fetching itself, and the sharing service the author chose.

Open questions

1. How is the Pipeup program made?

Recommended: from the same code as the npm command, with a JavaScript runtime built in, so the two can't disagree. The cost is size: roughly 60 to 110 MB, depending on the runtime. A small native rewrite would be a few MB but would be a second program to keep in step. The built-in runtime is a tool's, not something a page loads, so it doesn't break the no-dependencies rule for the library and add-ons. Please confirm you read the rule that way.

2. Apple notarization

Recommended: install with one line first, notarize later. macOS runs a file curl downloaded, so the install line works without it. A browser download is blocked until the program is notarized, which needs an Apple developer account. Windows SmartScreen warns about unsigned programs in the same way.

3. Pick up an unsigned replies file by itself?

Recommended: yes, with the agents add-on, and always asking first (Screen 4). Today the page reads the replies file only when it lists an agent, and keeps only signed replies. The clipboard covers Macs and Windows; the file covers Linux without a clipboard tool and agents in a sandbox.

4. Should the setup page suggest a service?

Recommended: no. It lists them, by how long each keeps comments, with nothing selected. §11 says Pipeup never picks a service, and a suggestion from Pipeup's own site would read as a pick.

5. A Python path, or signing with openssl on Linux?

Recommended: neither. A new Mac has no working python3, and Python's standard library can't sign or open a shared copy. openssl can sign on Linux but not on a Mac, and rebuilding Pipeup's signed form in shell would be fragile. The clipboard and the file need no signing; the program signs.

6. Should the setup page also add Pipeup to a page?

Recommended: later, on the same page. It would do what pipeup init does, for an author with no agent at all. Ada's page was made by Claude, so Ada doesn't need it now.
