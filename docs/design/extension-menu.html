One menu, built for the job

The extension's toolbar menu, redrawn for someone whose job is to comment and then get the comments to whoever asked. Agreed with the maintainer, 23 November 2026; to be built for 1.1.0.

23 November 2026 · Spec: EXTENSION_SPEC.md §3, §4a, §5 (change log, 2026-11-23) · From the newcomer's first run in Safari (driven by the UI test) and Chromium · Light mode only, like every design page.

What changes. Before the first comment: one button and one sentence, where today there is a button, a switch, a shortcut and a link to an empty list. Once Pipeup is on: six rows and More, where today there are eleven rows, a status line and a footer. Copy is one press. Everything that is a preference or a way out moves under More. The second menu on the page goes. Nothing is removed from the product; it moves.

What stays the same. Comment on this page as the one way in. What each row does. Pipeup itself on the page. Which rows each browser gets (Safari still has no pin and no Send to my agent).

The newcomer's path, after the change

1 · First press

"Oh. One button, and it says what will happen."

The menu says: click anything on the page to comment on it, and comments stay in this browser until you copy or send them. No questions before the first comment.

2 · First comment

"Saved. And it tells me where to go next."

After Return, once only, one line:

Saved in this browser. Press Pipeup in the toolbar when you're ready to send them.
3 · Back to the menu

"Copy comments. That's the one."

Six rows, one of them bold. Copy is a single press; the text pastes into a message, an email or an AI chat. More holds the rest.

More opens in place, the way Copy comments opens today, and folds back with ‹, Esc or ←. It holds everything a person sets once or rarely: the look, hiding, pinning, Always on (for local pages on a localhost page), the add-ons' own rows, the way out, and Settings.

Settings opens the page that today is called "Comments you've made". It keeps that list first, under that name, then the extension's settings, then one line for add-ons that opens to them.

Unchanged in what it does. Copy loses its submenu: one press copies the readable text, which is also the Markdown an AI can act on. "As text" goes; the Markdown reads as text when pasted.

On the page: one menu fewer

In Safari, Your comments on this page opens Pipeup's own panel on the page. That panel's bar has a "…" that opens a second menu with the same rows as the toolbar menu. In the extension that "…" goes: the bar keeps the name and the Comment switch. Each thread keeps its own "…" (Edit, Delete, Resolve), which is about that comment, not about Pipeup.

Not in this change

  • The comment-mode hint on the page, which lists five instructions on the first visit. That is Pipeup's own (functional spec), and gets its own proposal: one sentence the first time, the rest later, one at a time.
  • What happens on the page after Return (a reply field opens, the next block lights up). Also Pipeup's own.
  • Safari's permission dialog, which Pipeup can't change.

Open questions for the maintainer

  1. Should Keep comments beside the page stay at the top level in Chrome and Firefox, where the side panel is the main way to read comments? The sketch puts it under More because it is set once per site.
  2. Is Send to my agent the right third row, or should it come first where an agent is set up, with Copy second?
  3. The one-time line after the first comment: on the page by the comment, or as a change in the toolbar button's badge? The sketch says on the page.
