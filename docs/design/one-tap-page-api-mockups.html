One tap to comment, and a page that can drive Pipeup

Ada built a trip itinerary with Pipeup 0.8.2 and shared it with Lee. To make it work for them, she had to build her own Comment button, her own selection button and her own name field, by faking keystrokes and reading Pipeup's internals. Each of those workarounds points at something Pipeup should do itself.

What changes

  • One tap on the comment control starts commenting, and another stops it. Today the first tap opens the menu, and Start commenting is a switch inside it.
  • Selecting words offers a comment outside comment mode too. Today selecting words outside comment mode does nothing, and Ada's reviewers concluded that commenting on text didn't work.
  • A page can drive Pipeup: turn comment mode on and off, know when it changes, set the reviewer's name and know when they change it, and learn why Pipeup didn't start.
  • Settings can go on Pipeup's own script line or be given when the page starts Pipeup, not only on <html>. Hosts such as claude.ai Artifacts wrap the page in their own <html>, so attributes put there are lost.

Screen 5 · Settings where the host lets you put them

claude.ai Artifacts, and other hosts that wrap a page, write their own <html>. The same settings can now sit on the line that loads Pipeup.

Today · lost on Artifacts
<html data-pipeup-doc="…" data-pipeup-layout="bubbles"> <!-- the host replaces this tag with its own --> <!-- Ada's workaround --> <script>document.documentElement.setAttribute("data-pipeup-doc", "…");</script> <script src="…/pipeup.js" integrity="…"></script>
Proposed
<script src="…/pipeup.js" integrity="…" data-pipeup-doc="…" data-pipeup-layout="bubbles"></script> <!-- or, for a page that starts Pipeup itself --> Pipeup.mount({ doc: "…", layout: "bubbles" });

Every setting <html> takes works in either place. pipeup init puts them on the script line for a page that a host will wrap, and pipeup check reads them from all three places.

Proposed spec wording

Changes to §4 (Adding Pipeup), §5 (Starting a comment) and §7 (The comment control), and a new §4a.

§4 · Adding Pipeup to a page
Every setting a page can put on <html> can also be put on the line that loads Pipeup, or given when the page starts Pipeup itself, so pages on hosts that write their own <html> (such as claude.ai Artifacts) need no extra code. A setting given in more than one place takes the value given when the page starts Pipeup, then the one on Pipeup's line, then the one on <html>; the check names the places that disagree.
§4a · Working with the page's own code (new)
A page's own code can turn comment mode on and off, and is told once the change has happened.
It can ask whether comment mode is on, and is told each time it changes, however it changed: Pipeup's control, the shortcut, Esc, or the page itself.
It can set the reviewer's name at any time. Pipeup keeps it as if the reviewer had typed it, and the page is told each time the reviewer changes it in Pipeup.
When Pipeup can't start, the page can learn why in words (for example, another copy of Pipeup is on the page), as well as the console.
None of this reaches inside Pipeup's own interface, and none of it can read, write or change a comment.
§5 · Starting a comment
Selecting text offers commenting only in comment mode. Outside it, selecting text offers nothing and the page behaves as normal.
Selecting words offers commenting in and out of comment mode, with the same comment icon in the same place. Starting a comment from it outside comment mode doesn't turn comment mode on, and the page keeps working as normal. An author can turn this off, so that outside comment mode selecting words offers nothing.
A link's words can be selected and commented on like any others; commenting on a link as a whole is done in comment mode.
§7 · The comment control
In comment mode, clicking it opens All comments… Otherwise, clicking it opens its menu…
Clicking or tapping the comment control turns comment mode on; doing it again turns it off. Comment mode's hint says how to stop.
Pointed at, the control's reach shows its shortcut and ⋯, which opens the menu. By touch, pressing and holding the control opens the menu, and the first time comment mode starts by touch its hint says so. From the keyboard, ↑ or the menu key on the focused control opens the menu.
The menu keeps its rows, and Start commenting stays in it with its switch, so the menu still shows the state and the shortcut. All comments is reached from the menu.

Open questions

1. How does touch reach the menu?

Recommended: press and hold, taught once by comment mode's hint (A). It keeps the control as small as it is today. The ⋯ tab (B) is easier to find but covers twice as much of a phone's page.

2. Selection outside comment mode: on by default?

Recommended: on, with an author switch to turn it off. Selecting words is how most people expect to comment. Apps where people select to copy can turn it off.

3. Should the page also be able to start a comment on a given element or selection?

Recommended: not now. Ada asked for it to build her own selection button, which this proposal makes unnecessary. Add it if another page needs it.

4. All comments while commenting

Decided: from the menu. Today a click in comment mode opens All comments. With one click toggling comment mode, All comments is the menu's row. The count sits inside the same 32 px square, too small to be a second target.
