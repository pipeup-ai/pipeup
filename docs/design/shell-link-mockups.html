A live link made of shell commands

Ada is planning a trip to Lisbon that starts Friday. Claude, running on Ada's Mac, made the itinerary and shows it at http://localhost:3000. Ada left six comments. For Claude to read them and answer straight into the page, today's live link needs npx pipeup watch, and Ada's Mac has no Node. Every Mac already has bash and nc, and that's enough for the link.

What changes

  • A shell link. A short script, published with each Pipeup release, does the live link's job (§15c) with only bash and nc, which come with macOS and most Linux. The agent can read all of it before running it.
  • It sits beside whatever already shows the page: a local preview at localhost, or the page opened as a file. It doesn't serve the page itself.
  • It prints a connect address, the page's own address with the link added. Opening it once tells the page where the link is, and Share with my agent appears in the menu, off until Ada turns it on.
  • Turned on, the page sends its comments to the link, which writes them to a file next to the page. Claude reads that file with cat.
  • Claude answers with the same replies block it would paste, piped into the script, which writes the replies file. The page finds the replies within seconds and asks Ada before adding them, because no Mac can sign them without Node.

What stays the same

  • Nothing leaves the computer. The link listens on 127.0.0.1 only, accepts only the page's own address and a secret made fresh each run, and sends nothing anywhere.
  • Share with my agent is off on every load, and its hint says what it sends and where (§15c).
  • Agents still only reply and mark threads addressed. Copy and paste (#96, #98) still works everywhere, and pipeup watch still works where Node is.
  • No telemetry, and nothing added to the page's own content.

Tried on this Mac

A 40-line prototype on macOS 26.7 with its own bash 3.2 and nc. The page was shown by a separate local server at localhost:3000; the link listened on 127.0.0.1:7342.

Proposed spec wording

Changes to §15c (A live link to an agent on this computer) and §15b (What agents are told).

§15c · Starting it
The author starts a link for a page file with one command on their own computer.
The author starts a link for a page file with one command on their own computer: pipeup watch where Node is, or the shell link, a short script published with each release that needs only what macOS and Linux come with.
The shell link works beside whatever already shows the page on this computer (a local preview address, or the file itself) and doesn't change either. It prints a connect address: the page's own address with the link added. Opening it connects the page to the link.
Like pipeup watch, it listens only on this computer, accepts only the page it was started for and a secret made fresh each time it starts, and says in words where it is and how to stop it.
§15c · Sharing is a click
A page not shown through a link has no such switch.
The switch is shown on a page shown through pipeup watch or opened from a shell link's connect address, and on no other page.
If a send doesn't get through, the page tries again for a few seconds before it turns the switch off and says the link isn't reachable.
Nothing Pipeup copies or shows carries the link's address or secret.
§15c · What the agent can do
With the shell link, the agent reads the comments from the file the link keeps next to the page, and answers by giving the script its replies block, which the script writes to the replies file.
Replies that come this way and aren't signed by an agent the page lists wait for the person: the page says in words how many arrived and from which agent, and adds them only when the person agrees. They show as "added by you", and follow every rule for agent replies (§15b).
§15b · What agents are told
An agent on the person's computer that can run commands but has no Node uses the shell link, and never asks the person to install anything to answer comments.

Open questions

1. Where the connect address carries the link

Recommended: in the query (?pipeup-link=…). The part after # would never reach a server, but decks and many apps use it for their own place, and the link would break it. The query does reach the local preview server, which is on the same computer. Opening the page again without it leaves the link off.

2. Add unsigned replies without asking while the switch is on?

Recommended: no, ask each time replies arrive. Anything that can write the page's folder can write the replies file. One click per round is the cost of not needing Node. Signed replies from a listed agent still appear by themselves.

3. Linux's different nc programs

Recommended: the script checks which one it has and says plainly when it can't listen, pointing to copy and paste. Debian and Ubuntu ship one that works the way macOS's does; some others need different options, and some have none.

4. Pages on a website

Recommended: not for now. A page on https:// reaching 127.0.0.1 is blocked by some browsers and needs the person's permission in others. Pages on websites keep copy and paste.

5. Windows

Recommended: later, as a PowerShell script doing the same job, once the shell link has settled.

6. Considered and left out: driving the browser

On a Mac, osascript can run code in Safari or Chrome directly, with no link at all. But it only works after the person turns on a developer setting that lets any program with permission run code in every tab, banking included. That's too much to ask for reading comments.
