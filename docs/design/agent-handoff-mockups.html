Hand comments to any agent, however isolated

Sam reviewed today's briefing, which Muse made, and asked Muse to act on the comments. Muse couldn't open the page, couldn't see Sam's browser, and had nowhere to put its answers. Agents differ in what they can reach, and the page can't tell which kind it's being handed to. So the default should assume the agent can reach nothing, and carry everything both ways through copy and paste.

What changes

  • Copy for my agent copies the open comments together with how to answer them. Today it copies only the instructions, and an agent that can't open the page has to ask for a second paste.
  • The copied text says plainly that the comments are kept in Sam's browser, not in the page's file. Muse spent a turn defending itself against "you overwrote the page"; neither side knew where the comments lived.
  • An agent that can't write next to the page answers with a replies block in its chat message.
  • A new menu item, Paste my agent's replies, reads that block. The page shows what it found before adding anything, and the replies appear in their threads marked as pasted by Sam.
  • The faster routes (the live link and the reply command) stay, as shortcuts for agents that can use them. No agent needs them.

Proposed spec wording

Changes to §15b (Showing that a page is ready; What agents are told) and §15d (What the add-on does).

§15b · Showing that a page is ready for an agent
…a second choice, Copy a prompt for my agent… It carries no comments and no keys.
With the agents add-on, the menu has Copy for my agent, which copies the page's open comments (each with its id, where it is and its words, and any replies) together with how to answer them, so an agent that can't open the page or its folder has everything in one paste. It says how many resolved comments it left out. It carries no keys.
The copied text says that the comments were left in the reviewer's browser and are not in the page's file.
It names the faster routes (the live link and the reply command) for an agent that can use them, and works without them.
With the agents add-on, the menu has Paste my agent's replies. The person pastes the agent's answer; the page says in words what it found (how many replies, from which agent, how many say addressed, and how many it will leave out and why) and adds nothing until the person agrees. If it finds none, it says so and offers to copy a request for the agent to answer in the replies block.
Pasted replies show in their threads under the agent's name, with the AI marking and "pasted by you". They follow every rule for agent replies: they never resolve, reopen, edit or delete, and can't change a person's comment. They are kept with the comments in this browser.
§15b · What agents are told
An agent that can't write the replies file (for example a chat with no files) says what it would have replied, in a form the author can paste, and does not pretend the page was updated.
An agent that can't write the replies file answers in one replies block the page can read, says what it changed and where, and does not say the page was updated.
An agent never looks for comments in the page's file, and never asks the author to list it for replies it can't deliver.
§15d · What the add-on does
Reads replies the person pastes, as above. Pasting sends nothing anywhere.

Open questions

1. Accept pasted replies from an agent the page doesn't list?

Recommended: yes, marked "pasted by you". The listing guards the replies file, which anyone who can write the folder could fill. A paste is Sam's own act, made after seeing what the page found. Requiring a listed key would send Muse back to asking Sam to edit the page.

2. Should Copy for my agent include resolved comments?

Recommended: open ones only, with a line saying how many were left out. Reopened threads are open, so "Still not right" still reaches the agent with its history.

3. Do pasted replies travel when the page is shared?

Recommended: yes, like any reply, when the page has a sharing add-on. Without one they stay in this browser with the comments.
