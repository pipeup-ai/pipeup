Pipeup for browsers

An extension that lets anyone comment on any web page with Pipeup, even pages that never added it. It installs from each browser's own store, and it ships from the same release as the npm package, with the same version and the same files.

What a browser extension is

An extension is a zip of plain web files: a manifest.json that names it and lists what it may do, icons, and scripts. Each browser's store reviews and signs that zip and then updates it on people's computers by itself. Two rules shape everything below:

  • Everything ships inside the zip. Stores don't allow an extension to load code from the web, so the extension carries its own copy of pipeup.min.js and the add-ons instead of loading them from jsDelivr.
  • Every update goes through review. npm publishes in minutes; a store takes from hours to a few days. The release plan below is built around that gap.

Every major browser now uses the same extension format (Manifest V3, the "WebExtensions" standard). That means one code base with a few manifest lines that differ per browser, not four extensions.

2. What happens, lane by lane

The extension never puts Pipeup into a page by itself. It waits for the reviewer, checks the page, then adds its own copy, which the page's scripts can't see or change.

The extension asks for no access to sites until the reviewer presses the button; that press grants it for that one tab. "Always on for this site" asks the browser once, for that site only.

5. One release, every store

The same tag that publishes npm today also builds the extension and sends it to each store. The extension's copy of pipeup.min.js is the very file on npm, byte for byte, and the release checks that.

StoreWhat the release sendsHow it's sent
ChromeThe zipChrome Web Store API: upload, then publish; it can hold a release back and roll it out in stages
EdgeThe same zipEdge Add-ons API
FirefoxThe same zip, plus a zip of Pipeup's source and how to build itMozilla's web-ext tool. Mozilla asks for the source of any minified file so its reviewers can rebuild it
SafariThe same files, wrapped in a small Mac and iPhone appBuilt on a Mac runner with Xcode and sent to App Store Connect; Apple is also rolling out a web packager that takes the zip directly

As with npm's trusted publishing, the first listing in each store is made by hand once (name, icons, screenshots, privacy answers). Every release after that is automatic. The release workflow checks each store's key before it publishes anything, so a missing key stops the release early instead of halfway through, the lesson from 0.9.0.

6. Bug fixes

A fix is one patch release, as today. What differs is how fast it reaches people:

  • Pages that load Pipeup from npm or a CDN get it in minutes.
  • People using the extension get it once each store has reviewed it (hours to a few days), and then their browser updates it on its own within a few hours.
  • An urgent fix can't skip review in any store. Chrome lets us pause a staged rollout, which keeps a bad release from reaching everyone while the fix is reviewed. A store never takes a version back; "rolling back" is a new patch that carries the older code.
  • No remote switches. The extension never fetches settings or code from us; that keeps it private and keeps reviews quick, at the cost of fixes waiting for review.

The release check reports each store as "live" or "waiting for review", so it's clear which fixes have reached whom. The menu's About line shows the same version number on a page and in the extension.

7. Pre-releases

Stores accept only plain numbered versions, so 0.10.0-beta.1 can't go to the main listings. Pre-releases go to separate testing listings instead: an unlisted "Pipeup Next" in the Chrome store (installed by link), a signed Firefox file that we host on the site, and TestFlight for Safari. The stable listings only ever get stable releases.

8. What it ships with

  • Pipeup and the add-ons that work on any page: Share, Live, Voice, Emoji, Agents, GitHub and the rest that don't need the author's markup. The reviewer turns each on from the extension's settings, as an author would on a page.
  • Not included: Inline, which needs asks written into the page, and the update notices, because the store updates the extension.
  • No analytics, no telemetry, nothing sent unless the reviewer turns on an add-on that sends, same as today.
  • Size: under 1 MB in all; stores and browsers don't mind.

9. Decisions for you

Where are comments kept? Recommended: in the extension, by page address, so they follow the reviewer across tabs, can't be read or cleared by the site, and show in "Comments you've made". The other choice is the site's own storage, as a page with Pipeup built in does; simpler, but the site can wipe them.

Can an agent reach the extension's Pipeup? Recommended: no. A page's scripts can't see the extension's copy, and that is what keeps the reviewer's comments private. Agents get comments the ways they do today: Copy for AI, Share, or the agents' mailbox.

Which browsers first? Recommended: Chrome, Edge and Firefox together (one zip, free or $5), then Safari once the Apple Developer account and a Mac release step are in place. Safari is the most work: an app wrapper, a yearly fee and its own review.

Pre-releases in stores from day one? Recommended: not yet. Ship stable only, add the testing listings after the first stable extension release.

10. The spec change

Proposed as a new, short spec, docs/EXTENSION_SPEC.md, beside the website's. Functional requirements only:

Pipeup for browsers

  • A reviewer can add Pipeup to any web page from the browser's toolbar, or with a shortcut, on Chrome, Edge, Firefox and Safari, and on the browsers that install from those stores.
  • Pipeup works there as it does on a page that has it built in: the same control, menu, comments and add-ons.
  • Nothing is added to a page until the reviewer asks. "Always on for this site" adds it whenever that site is opened, and asks the browser's permission for that site only.
  • On a page that has Pipeup built in, the extension steps aside and says so. On pages browsers keep closed to extensions, it says why it can't run.
  • Comments made with the extension are kept in the browser by the extension, by page address; the site can't read or remove them. The reviewer can see every page they've commented on.
  • The toolbar button shows how many open comments the current page has.
  • Each Pipeup release is also an extension release with the same version and the same Pipeup files. Stores review each release; until a store has, that store offers the previous version.
  • The extension sends nothing anywhere and loads no code from the web; only add-ons the reviewer turns on send, as they say.

What changes, in one place

  • New: an extension in the repo (apps/extension), built from the release's own files.
  • New: a release step per store, a store-key check before publishing, and store status in the release check.
  • New: a short spec, a design note, four store listings and an Apple Developer account.
  • Unchanged: Pipeup, its add-ons, npm, the CDNs and the site.
